## 2. 后端：regeo 逆地理编码与 location 点（PASS）

### 2.1 代码审查

- `backend/amap.py::AmapClient.regeo(location)`：请求 `GET /v3/geocode/regeo?location=...`；解析 `regeocode.formatted_address` 与 `addressComponent.city/citycode/province`；**直辖市 `city=[]` 时退回 `province`**；回显 `location`（6 位小数）；复用 `_get` 的超时（10s）、错误映射与 Key redact 机制。
- `backend/planner.py::resolve_points_live`：仅对 `location` 点调用 `regeo`（address 点仍走 geocode 且按地址去重）；`try: geo = client.regeo(...) except ApiError: geo = {}`，**逆地理失败不拖垮整次规划**；未显式命名的点用 `formatted_address` 展示，显式 `name="我的位置"` 时保留该名称；`formatted_address/city/citycode` 由 regeo 补全（公交规划可用）。
- 契约文档已同步：3.1 版本示例 0.3.0；3.3 location 说明；§5 增加 regeo 接口说明。

### 2.2 单测证据（离线 mock，不联网）

## 3. 前端：起点「定位」按钮（PASS，DOM 实测）

### 3.1 代码审查（smoke 新增 11 项）

- 定位按钮仅在**起点行**动态渲染：`data-locate-index`、`.btn-locate`，文案「定位 / 重新定位 / 定位中…」，只出现在 `pointKind(index)==='start'`。
- `handleLocate()`：检查 `state.loading`、`window.isSecureContext`（HTTPS/localhost 限制）、`navigator.geolocation.getCurrentPosition` 可用性；成功回调校验经纬度有限性后写入 `state.pointLocations[index]` 与 `state.points[index]="我的位置"`，重绘输入框并聚焦。
- 提交 payload：定位点返回 `{location:"lng,lat"(6 位), name: address||'我的位置'}`，非定位点仍为 `{address}`。
- 失败路径：`locateErrorMessage()` 覆盖 code 1（权限拒绝）/2（不可用）/3（超时）/其他，均有可读 message+hint。
- 用户手动修改起点文本会清除 `pointLocations[index]`、`is-located` 样式与按钮文案，避免「我的位置」与实际地址不一致；新增/删除途经点时同步维护 `pointLocations` 数组。
- CSS：`.btn-locate`、`.point-input.is-located` 存在；`node --check web/app.js` rc=0。
